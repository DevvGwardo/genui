# Changelog

All notable changes to this project are documented in this file.

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)-style sections, one entry per loop ID from [LOOPS.md](LOOPS.md), SemVer release headings (`## Unreleased` until v1.0.0 is tagged).

## Unreleased

- docs: add `LOOPS.md`, the 30-loop improvement queue (LOOP 0 scaffolding), plus `CHANGELOG.md`.
- feat(A1): add `schema/v1.json` — exact JSON Schema 2020-12 mirror of the v1 `render_ui` payload contract (4 widget types, every documented bound, `additionalProperties: false`); runtime-only rules that JSON Schema cannot express (16,384-byte cap, table row length, checklist id uniqueness) are called out in `$comment`s. Verified against ajv 8.17.1: 34/34 cases, accepts a 4-component payload, rejects an unknown key.
- docs(A2): add `docs/contract.md` — single source of truth for every v1 bound — and `tools/check-bounds.mjs`, a zero-dependency plain-Node checker that multiset-diffs the table against `skills/genui/SKILL.md` (19/19 bound tokens match; a mutated bound makes it exit 1).
- docs(A3): add `docs/errors.md` — error → cause → fix register for `bad_args` (incl. unknown widget type), `not_enabled`, `app_unavailable`, `too_large`, plus bound violations and duplicate checklist ids whose codes SKILL.md does not name (explicitly marked, not guessed) — and `tools/check-errors.mjs`, which fails if any error-shaped token in the repo is missing from the register (negative-tested). Also aligned an over-broad `bad_args` claim in `schema/v1.json` with SKILL.md's exact wording.
- docs(A4): `docs/contract.md` gains a Version negotiation section — v1 is `version: 1` only (no default), unknown versions must never be dispatched or translated, and v2 does not exist (it would arrive as a separate `schema/v2.json` plus a section update, never as an edit of v1). `docs/errors.md` registers the unknown/missing-version rejection without guessing a code; schema harness now also rejects `version: 2`, `"1"`, and missing (37/37).
- docs(A5): add `docs/terminology.md` — canonical terms (Hermes Agent, Hermes Desk, genui, Generated UI, widget/component, v1 payload contract) and a banned-variants register — plus `tools/check-terms.mjs`, which enforces zero drift across README/SKILL/docs (negative-tested). Fixed README's "Hermes Desk profile" → "Hermes profile" and SKILL's "the desktop dispatch" → "Hermes Desk".
- feat(B1): skill frontmatter description now carries the `genui` trigger word plus five natural-language triggers ("genui", "render a table of ...", "render a stat card showing ...", "render a bar chart of ...", "render a checklist for ...") while keeping the tool name and widget kinds; matches `/genui/i` and stays YAML-safe.
- docs(B2): SKILL.md gains "When to Use" (explicit genui invocation, compact summaries, local checklists, contract-deliverable values) and "When NOT to Use" (markup/links inside cards, content over the card limits, callbacks beyond the local checklist toggle, Desk unavailable) — each with concrete scenarios, no new bound tokens.
- docs(B3): SKILL.md gains "Minimal Examples" — four isolated single-component payloads (stat, table, bar_chart, checklist), each a complete valid `render_ui` argument; all fenced payloads in the file (5/5, including the existing 4-up) validate against `schema/v1.json` via an extraction check, negative-tested.
- docs(B4): SKILL.md's per-widget prose limits are replaced by a single Quick Reference table (widget | required fields | caps); the string filter moved to its own "Text Restrictions" section. Bound multiset stays 19/19 against `docs/contract.md` — mechanically proving no bound is stated twice (a re-added prose bound makes `tools/check-bounds.mjs` exit 1).
- docs(B5): SKILL.md gains a Pitfalls section — 8 concrete anti-patterns, each naming the failure mode and the fix (markup/links in strings, table row/column mismatch, retry storm on disabled profiles, duplicate checklist ids, byte-cap overflow, treating cards as verified data, wrong/omitted version, genuiOccurrence spoofing). No new bound or error tokens.
- docs(B6): SKILL.md gains a "Pre-flight Self-check" — 11 checklist lines, each naming the exact rejection it prevents. A temp extraction checker verifies every named schema keyword exists in `schema/v1.json` and every error code in `docs/errors.md`: 11/11 lines map (9 schema-keyword lines, 2 annotated runtime-only rules). No new bound or error tokens.
- docs(B7): SKILL.md gains "Pruning Under the Byte Cap" — over-cap payloads are pruned by six ordered, deterministic steps (measure the exact argument; drop non-required fields in the fixed order detail/unit/checked; drop trailing rows; drop trailing items; drop whole components from the end; stop and report), with explicit tie-breaks and floors and no judgement calls; the byte-cap pitfall now points to it. Verified by a temp demo that re-implements the steps on a valid oversized example: byte-identical traces across two runs and the pruned payload still validates against `schema/v1.json`.
- docs(B8): SKILL.md states the non-ASCII string policy (printable accented Latin, CJK, and standalone emoji pass; banned control/format/bidi characters — including zero-width-joined emoji — are rejected) with an 11-row allowed/blocked example table of JSON string literals. A temp checker validates every table row against `schema/v1.json`: 3 allowed accepted, 8 blocked rejected — 11/11.
- docs(C1): README "How it works" and "Why data-only?" are now fully textual: the four pipeline steps carry their guarantee details (schema kept out of context; no HTML tags or URLs; server-minted token prevents spoofing; checklist state stored locally), and the why-to-use-it comparison is a text table (injection surface, theme breakage, webview memory overhead, broken toggles versus the zero-injection trust boundary, native design system, compact payloads, zero-token checklists). Temp checker: 29/29 image-derived claims present as text; both images remain embedded. The graphic's unverified magnitudes (e.g. the 90% token figure) were transcribed as qualitative design rationale, not asserted — the 90% figure remains pixel-only pending C5.
- docs(C2): README gains license/version/last-commit badges (all three verified to return live SVG) and a Contents table; all 8 TOC anchors resolve under GitHub slug rules (temp checker exit 0, every h2 covered).
- docs(C3): README gains "Verify the install" and "Uninstall" subsections plus a "Troubleshooting" table (declared error codes only, copy-pasteable file checks). All documented shell commands were executed verbatim in a sandboxed HOME via git-bash: verify found the installed skill, uninstall removed it cleanly; TOC updated (9/9 anchors resolve).
- docs(C4): README install instructions become a Bash/PowerShell matrix; both install the skill as a direct child named `genui` (`<skills-dir>/genui/SKILL.md`), and the stale `desktop-ui/genui` wrapper path is fixed everywhere (verify, uninstall, troubleshooting now include PowerShell variants). Both command sets were actually executed on this machine in sandboxed HOMEs: Git Bash and a child pwsh each cloned, installed, verified, and uninstalled the skill with exit 0.
- docs(C5): the "90% token reduction" claim is adjudicated by measurement and the unsourced figure retired. New `tools/measure-context-reduction.mjs` (zero-dependency plain Node) benchmarks one representative dashboard (stat + 8-row table + 6-bar chart + 6-item checklist) as the compact genui payload (949 bytes) versus the same content in self-contained HTML at three styling levels: minimal 1,024 bytes (7.3% reduction), typical styling 3,500 bytes (72.9%), rich styling 4,377 bytes (78.3%) - basis UTF-8 bytes, since no model tokenizer is available in this environment. No representative baseline reproduces 90%, so `docs/context-reduction.md` becomes the measurement of record (methodology, captured output, caveats, claim status), README states the measured ≈73% (typical) / ≈78% (rich) figures, and a caption under the why-to-use-it graphic points readers to the doc; the graphic itself stays as a design illustration.
- docs(D1): add `examples/valid/` - six committed, complete valid `render_ui` arguments validated against `schema/v1.json`: one per widget (`stat.json`, `table.json`, `bar-chart.json`, `checklist.json`), one four-up payload using all four widget types, and one boundary case at the table maximum (6 columns x 20 rows, every row length equal to the column count). A temp ajv harness plus mirrors of the three runtime-only rules validates all six files and asserts the acceptance shape; a sandbox negative test with a row-length mismatch exits 1. `tools/validate.py` (D3) and CI (D4) will gate these files going forward. Also: the environment note is corrected - Python 3.12.7 is available via the `py` launcher (`python3` on PATH is only a Store alias stub), so D3-D5/F2 are not blocked on Python.
- docs(D2): add `examples/invalid/` - seven deliberately invalid payloads, one per rejection class, plus `manifest.json` naming each file's expected outcome. Four cases assert codes named in `docs/errors.md` (`extra-property`, `unknown-widget-type`, `wrong-type` - `bad_args`; `too-large-payload` - `too_large`: schema-valid, 6 columns x 20 rows of 160-character cells, compact 19,770 bytes over the 16,384 cap); three are documented rejections whose code is not named in v1 docs (7-column `bound-violation`, `unknown-version`, `duplicate-checklist-id`), so they expect `null` and assert the exact rejection class instead - no guessed codes. A temp ajv checker classifies each failure per widget branch and asserts the exact expected outcome: 7/7 exact; a two-expectation-flip sandbox negative test exits 1. `docs/errors.md` links the fixture set.
